# ShiftBot

> Часть портфолио: [сайт-портфолио](https://auryxn.github.io) — репозиторий сайта [site-admin](https://github.com/auryxn/site-admin).

> Telegram-бот для краткосрочных подработок: админ публикует смены, работники записываются в пару кликов.

## Что это (простыми словами)

ShiftBot — это MVP-бот в Telegram, который заменяет ручной поиск людей на короткие смены (переезды, расклейка, помощь на складе и т.п.).

- **Админ** создаёт «работу»: название, ставка €/час, количество часов, дата, время приезда, адрес, сколько человек нужно. Всё это вводится пошагово прямо в чате, затем проверяется на экране-превью и публикуется.
- **Работник** открывает бота, смотрит список доступных подработок, жмёт «Работать», вводит имя и фамилию — и записан. Может посмотреть «Мои работы», профиль и отменить участие.
- Когда на работу набралось нужное число людей, она автоматически переходит в статус «набрано», админ получает уведомление, а в карточке видно, кто именно записан.

Для кого: небольшие подрядчики/организаторы, которым нужно быстро собрать людей на смену без таблиц и звонков. Интерфейс — на русском, валюта — евро, часовой пояс — Europe/Vilnius.

## Возможности (реальные фичи)

**Для работника:**
- Список активных подработок с оплатой, датой/временем, адресом и числом свободных мест.
- Карточка работы и запись через кнопку «Работать» (FSM-диалог: имя + фамилия).
- «Мои работы» — список активных записей с возможностью отмены.
- «Профиль» — имя, @username, число активных и завершённых работ, дата регистрации.
- Помощь и заглушка выбора языка (русский / English / lietuvių).

**Для админа:**
- Пошаговое создание работы (название → описание → ставка → часы → дата → время → адрес → кол-во работников) с превью, публикацией и отменой черновика.
- Списки «Активные работы» и «Набранные работы» со счётчиками «набрано/нужно».
- Карточка работы: закрыть набор, удалить работу.
- Список работников по конкретной работе (имя, @username, Telegram ID).
- Рассылка всем работникам о новой подработке.

**Фоновые задачи (планировщик в процессе бота):**
- Напоминания работникам за ~24 часа и за ~2 часа до начала смены (с записью в `reminder_logs`, чтобы не дублировать).
- Автозакрытие прошедших работ: через 12 часов после старта смена помечается «завершено», заявки — тоже.
- Защита от гонок: запись на работу идёт под блокировкой строки (`FOR UPDATE`), повторная запись после отмены переиспользует существующую заявку (уникальность `(job_id, user_id)`).

**Статусы:**
- Работа: `DRAFT`, `ACTIVE`, `FILLED`, `CLOSED`, `COMPLETED`.
- Заявка: `ACTIVE`, `CANCELLED`, `COMPLETED`.

## Стек

- Python 3.12
- aiogram 3.x (Telegram Bot API, long polling)
- PostgreSQL + SQLAlchemy 2.x (async, `asyncpg`)
- Alembic (миграции)
- Pydantic / pydantic-settings (конфиг из `.env`)
- pytest + pytest-asyncio (тесты)
- Docker Compose (бот + Postgres)

## Установка и запуск

### Вариант A — Docker Compose (рекомендуется)

```bash
cd projects/shiftbot

# 1. Создать .env на основе примера
cp .env.example .env
# отредактировать как минимум BOT_TOKEN и ADMIN_IDS

# 2. Поднять бота и базу
docker compose up --build
```

`docker-compose.yml` поднимает сервис `bot` (собирается из `Dockerfile`) и `db` (PostgreSQL). Бот дожидается готовности базы и применяет миграции Alembic при старте.

### Вариант B — локально

```bash
cd projects/shiftbot

# 1. Виртуальное окружение и зависимости
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .            # зависимости берутся из pyproject.toml

# 2. Конфигурация
cp .env.example .env        # заполнить BOT_TOKEN, DATABASE_URL, ADMIN_IDS

# 3. Поднять Postgres (можно отдельным контейнером)
docker compose up -d db

# 4. Применить миграции
alembic upgrade head

# 5. Запустить бота
python -m app.main
```

### Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота от @BotFather |
| `DATABASE_URL` | строка подключения к PostgreSQL (async-драйвер) |
| `ADMIN_IDS` | список Telegram ID админов (через запятую) |
| `TZ` | часовой пояс отображения дат |

### Тесты

```bash
pytest
```

## Структура проекта

```
shiftbot/
├── app/
│   ├── main.py                    # точка входа: Bot, Dispatcher, регистрация роутеров, фоновые задачи
│   ├── config.py                  # настройки из .env (get_settings)
│   ├── handlers/
│   │   ├── start.py               # /start — регистрация пользователя, меню по роли
│   │   ├── worker.py              # меню работника: список работ, мои работы, профиль, помощь
│   │   ├── applications.py        # запись на работу и отмена записи
│   │   └── admin.py               # /admin: создание/публикация работ, списки, карточка, работники
│   ├── keyboards/                 # инлайн-клавиатуры (common, admin, job)
│   ├── states/                    # FSM-состояния форм (JobForm, WorkerNameForm)
│   ├── services/
│   │   ├── job_service.py         # запись/отмена под блокировкой, статусы набора
│   │   ├── notifications.py       # рассылка, напоминания 24ч/2ч, автозакрытие смен
│   │   └── formatting.py          # форматирование карточек и денег
│   └── database/
│       ├── models.py              # User, Job, Application, ReminderLog + enum'ы
│       └── repositories.py        # запросы к БД
├── migrations/                    # миграции Alembic (versions/)
├── tests/                         # test_regressions.py и др.
├── docs/
│   ├── AUDIT.md                   # аудит багов от 2026-09-17
│   └── EXCEL_EXPORT_SPEC.md       # спека будущего экспорта в Excel
├── docker-compose.yml
├── Dockerfile
├── pyproject.toml
└── .env.example
```

## Статус

**MVP в работе (прототип)** — на 2026-10-16.

Рабочий каркас: регистрация, публикация работ, запись/отмена, списки и карточки админа, напоминания и автозакрытие смен. Известные ограничения и баги зафиксированы в `docs/AUDIT.md` (в частности, часть админ-экранов требует eager-load связей, повторная запись после отмены, порядок удаления). Не реализованы: экспорт в Excel/CSV (спека — `docs/EXCEL_EXPORT_SPEC.md`), редактирование уже опубликованной работы, полноценная локализация.
